# Security Guidelines

Rules and conventions for contributing to ocp-secrets-management-console.
Agents and developers must follow these when modifying code in this repo.

## 1. Authentication and Authorization

- **All K8s API calls go through the console proxy.** Use `consoleFetch` from
  `@openshift-console/dynamic-plugin-sdk` for every Kubernetes API request.
  Never call the cluster API server directly; the console proxy handles
  authentication, CSRF, and impersonation.
- **Never store or forward tokens in frontend code.** The console session
  manages bearer tokens. `start-console.sh` passes `BRIDGE_K8S_AUTH_BEARER_TOKEN`
  to the containerized console only -- the plugin itself never touches it.
- **Never add `core/v1` Secrets to any RBAC role or watch.** This plugin
  displays CRD metadata (Certificates, ExternalSecrets, SecretProviderClasses,
  etc.) but intentionally never reads `core/v1` Secret data. Do not add
  `secrets` to any `apiGroups: [""]` rule.

## 2. RBAC -- Helm Chart ClusterRoles

Three tiered ClusterRoles exist in `charts/.../templates/rbac-clusterroles.yaml`.
When adding a new CRD kind, follow these rules:

| Role | Verbs allowed | Notes |
|------|---------------|-------|
| `{prefix}-view` | `get`, `list`, `watch` | Read-only. Add every new CRD here. |
| `{prefix}-delete` | `delete` | Destructive. Omit status-only subresources (e.g. `secretproviderclasspodstatuses`). |
| `{prefix}-admin` | `*` | Full access. Include all resources from view + delete. |

- Keep the operator's Go-side RBAC markers (in the controller) in sync with
  Helm templates. Both sources create the same three roles.
- The patcher ClusterRole (`patcher-clusterrole.yaml`) must never grow beyond
  `get`, `list`, `patch`, `update` on `consoles.operator.openshift.io`. It is
  scoped to a post-install Job, not the running plugin.
- Do not use `verbs: ["*"]` in view or delete roles. Reserve it for admin only.

## 3. Delete Confirmation Pattern

Every table that offers a Delete action must follow the established pattern:

1. Use `DeleteConfirmationModal` from `src/components/DeleteConfirmationModal.tsx`.
2. Require the user to type the exact resource name before the Delete button enables.
3. Issue the DELETE via `consoleFetch` with the correct API path built from the
   resource's model (`group`, `version`) and kind.
4. Show errors inline in the modal; never silently swallow delete failures.
5. Reset modal state (`isOpen: false`, `error: null`) on both success and cancel.

Do not add any destructive action (delete, patch, update) without a confirmation step.

## 4. Sensitive Data Handling in Inspect View

`ResourceInspect.tsx` masks potentially sensitive spec/status data behind a toggle:

- The `containsSensitiveData()` function checks for keys like `password`, `secret`,
  `token`, `key`, `privateKey`, `clientSecret`, `apiKey`, `tenantId`, `vaultUrl`,
  `parameters`, etc.
- When sensitive data is detected, the YAML dump is replaced with `********` by
  default; users must opt-in via the Switch toggle.
- Certificate status is always treated as potentially sensitive.
- **When adding new resource types to the inspect view**, add their
  security-relevant field names to the `sensitiveKeys` array.
- Never render secret values in table views -- tables show only metadata.

## 5. Container Security Contexts

All containers (plugin, operator, patcher job) must run with:

```yaml
securityContext:
  runAsNonRoot: true
  seccompProfile:
    type: RuntimeDefault
containerSecurityContext:
  allowPrivilegeEscalation: false
  capabilities:
    drop:
      - ALL
```

- Plugin Containerfiles must set `USER 1001` (nginx) or `USER 65534:65534`
  (operator). Never leave `USER root` in a final stage.
- Multi-stage builds: `USER root` is acceptable in the build stage only.

## 6. Dockerfiles and Supply Chain

- Base images must come from trusted registries: `registry.access.redhat.com`,
  `brew.registry.redhat.io`, or `quay.io/konflux-ci`.
- Pin digest-level references for production images (see `Containerfile.ocp-secrets-management`).
- Never install packages in the runtime (final) stage.
- `Dockerfile` (dev/upstream) may use tag-based references, but
  `Containerfile.*` (production/Konflux) must use digest pins.

## 7. Nginx / TLS Configuration

The plugin is served over TLS on port 9443:
- TLS certificates are mounted read-only from a Kubernetes Secret at `/var/cert`.
- The certificate Secret is generated by OpenShift's service-serving-cert-signer.
  Never hardcode or bundle TLS keys.
- Do not add proxy or upstream directives to the nginx config -- the plugin
  serves only static assets.

## 8. Webpack Dev Server CORS

`webpack.config.ts` sets permissive CORS headers and `allowedHosts: 'all'` for
the dev server. These settings must remain in the `devServer` block only and
must never appear in production nginx config.

## 9. Frontend Input Handling

- URL path parsing in `ResourceInspect.tsx` extracts values from
  `window.location.pathname`. Since all API calls go through the console proxy
  (which enforces RBAC), path manipulation cannot escalate privileges.
- Delete confirmation comparison uses strict equality (`===`). Do not weaken
  this to partial or case-insensitive matching.
- All user-facing strings must go through `useTranslation`. Use parameterized
  `t()` calls (`{{variable}}`) for interpolation -- never concatenate raw input.

## 10. Environment and Secrets in Git

- `.devcontainer/dev.env` is gitignored. Never commit `.env` files.
- `integration-tests/.auth/` is gitignored. Never commit authentication artifacts.
- Do not add credentials, tokens, or pull secrets to `values.yaml` defaults.

## 11. Adding a New CRD / Resource Kind -- Security Checklist

1. Add view/delete/admin verbs to both Helm `rbac-clusterroles.yaml` and
   the operator's role builder functions.
2. Add the CRD name to `useOperatorDetection.ts`.
3. Create a table component that uses `DeleteConfirmationModal` for deletes.
4. If the inspect view may expose sensitive fields, update `containsSensitiveData()`.
5. Build delete API paths from model constants, not hardcoded strings.
6. Omit status-only subresources from the delete role.
